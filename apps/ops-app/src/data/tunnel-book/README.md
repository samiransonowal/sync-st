# The Tunnel Book

The single source of truth for how work gets done at Tunnel.

This is a living document. Everything here reflects current practice. If something you do at the studio isn't in here, either it needs to be added or what you're doing needs to change. Both are fine — but the Book and the work stay in sync.

## How to use this Book

- **Read it on your first day.** All of it. It's short on purpose.
- **Reference it during work.** The Marker & Colour System (03) and Delivery Checklists (06) are meant to be open on a second screen when you're doing the work.
- **Contribute to it.** Every correction you give or receive on the floor is a candidate Book entry. See `/10-contributing.md`.

## Structure

1. `01-data-and-ingest.md` — Server structure, trim protocols, naming conventions
2. `02-timeline-prep.md` — XML handling, conform checklist, layer conventions
3. `03-markers-and-colours.md` — The studio's shared visual language
4. `04-colorist-workflow.md` — Node trees, groups, versions, PowerGrades library
5. `05-conform-and-revisions.md` — Multi-XML protocol, change logs
6. `06-delivery.md` — Per-client delivery checklists (Hotstar, Netflix, Prime, etc.)
7. `07-client-communication.md` — Frame.io etiquette, notes logging, response protocols
8. `10-contributing.md` — How to propose changes to the Book


## Status conventions

Every entry in the Book is one of three states:

- **Canonical.** Agreed, documented, enforced. No marker.
- **`[PROPOSAL]`** — Suggested convention awaiting team consensus. Discuss before treating as canonical.
- **`[DEPRECATED]`** — Kept for historical reference but no longer in use. Scheduled for removal.

When in doubt, ask. When you've asked and got an answer, propose a Book edit.
